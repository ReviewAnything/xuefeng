## 各批次置信度

- **普通一本 / 普通二本 / 专科（11 省）**：官方省控线分数 + 官方一分一段表位次，**高置信**。
  - 未合并批次省（河南/四川）：一本=本科一批线，二本=本科二批线，专科=专科批线。
  - 合并本科批的新高考省（广东/江苏/河北/安徽/湖南/湖北/福建/重庆）：**普通一本 ← 特殊类型招生控制线（特招线，≈原一本线）**，**普通二本 ← 本科批线**，专科=专科批线（口径统一，跨省可比）。
  - 综合改革省（山东）：普通一本 ← 普通类一段线，专科 ← 二段线。
- **985 / 211（6 省官方，其余 25 省估算）**：6 省（河南/广东/四川/山东/河北/江苏）的 985/211 入门投档位次取自各省发布的 **2024 最低投档线及位次**（普通类本科批），**高置信**，接口标注 `official`。其余 25 省（含新覆盖的安徽/湖南/湖北/福建/重庆）仍用 gaokao-advisor 院校层次参数推算，**中置信**，标注 `estimated`。
  - 阈值含义：该省该科类「普通类本科批」最低投档位次（不含预科班/边防军人子女/医护/艺术/定向/单列等特殊类型；中外合作、较高收费等面向所有考生、仅费用不同的路径保留）。普通类裸分门槛高于此值。
  - 985/211 入门位次（部分代表，含难度系数前）：
    - 河南 物理：985 575/44463（中国农业大学中外合作）、211 509/133259（西藏大学）
    - 广东 物理：985 589/29731（西北农林科技大学）、211 529/100604（西藏大学）
    - 四川 理科：985 576/44683（山东大学）、211 505/128623（成都中医药大学中外合作）
    - 山东 综合：985 578/40066（中国农业大学）、211 522/128405（宁夏大学）
    - 河北 物理：985 568/38490（西北农林科技大学）、211 514/101439（东北农业大学）
    - 江苏 物理：985 606/26287（西北农林科技大学）、211 551/79873（西藏大学）
  - 同层次内各校正取线差异较大（顶尖 985 与末位 985 可差数万分），本值为「入门底线」，具体以各校招生网/考试院为准。
- **艺术类 / 体育类**：官方仅公布文化控制线（见各省略），未纳入专业级推算；当前复用普通类批次线并标注 `estimated`。

## 院校投档线：自托管种子与一键落库（S6）

`school_lines`（逐校投档线）原先只能靠 `scripts/import_crawler_school_lines.py` **现拉**上游
公开爬虫仓库 `1837620622/gaokao-admission-crawler`。那是第三方开源项目，**随时可能下架、
改名或被清空**——一旦如此，新机器 clone 本仓库后将无法重建任何校线数据。

S6 由此把数据收归仓库自带：

| 种子 | 来源 | `data_source` | 说明 |
| --- | --- | --- | --- |
| `school_lines_estimated_real.json.gz` | 由 `scripts/export_school_line_seed.py` 从已入库数据导出的**快照**（掌上高考 2025 真实抓取，14020 行 / 30 省） | `estimated_real` | 仓库自持副本，随仓库提交；上游下架也能重建 |
| `admission_official_2024.json` 的 `school_tier_lines` | 各省考试院公布的 985/211 入门投档（普通类本科批），6 省 / 2 科类 | `official` | 真实官方口径，落库时 `group_code` 用层次（985/211）占位 |
| `backend/data/official/*.json\|csv` | **运营投喂**的省考试院逐校投档原表（S7-A） | `official` | 目录随仓库提交但**不预置数据**；缺来源链接的行一律拒收 |

**一键落库**：管理端「院校投档线 → 一键落库」点一次即可，底层是
`POST /api/admin/school-lines/import-seed`（`dry_run=true` 先看可落库行数）。
两者都按 (年, 省, 科类, 院校, 专业组/层次) **幂等 upsert**：重复执行只改变化的行，不会重复插入。

- 新环境（无 `*.db`、无网络）：`python scripts/export_school_line_seed.py` 不需要跑，直接一键落库即可重建。
- 刷新流程：重新采集（爬虫导入）→ `export_school_line_seed.py` 导出 → 提交新的种子文件。
- 官方行标 `official` 后，`/api/health` 的 `school_lines.has_official` 由 false 转 true，
  前端「数据权威性」横幅会显示官方覆盖。

### S7-B 种子治理：压缩 + 校验和 + 一致性

- 仓库只提交 **gzip 副本**（14020 行 JSON 明文 7.2 MB → gzip 约 256 KB，缩小约 28 倍）；
  读取时按后缀自动解压，明文路径仅作回退且已 gitignore，不再入库。
- 导出同时写 `data/seed.meta.json`（文件 sha256 / 行数 / 体积 / 生成时间 / 是否压缩）；
  `verify_seed()` 在落库前比对校验和，种子被改动或损坏会直接报错，不会半截落库。
- 管理端「一键落库」状态卡展示体积、校验和前 16 位与**库 / 种子一致性**（不一致提示重新导出）。

### S7-A 官方逐校投档线落地区

`backend/data/official/` 是官方原表的投放目录（含 `README.md` 说明字段与拒收规则，
但**不含任何数据文件**——我们手上没有可核实的省考试院逐校原表，也不允许把抓取数据标成官方）。

- 一键落库会自动扫描该目录；也可经管理端「官方逐校投档线落库」上传 CSV/JSON。
- 强校验：校名匹配教育部名单、省份/年份/分数位次合法，且**每行必须带 `source_url`**，
  否则整行拒收并给出原因（宁可少落，也不乱标）。
- 来源域名不像考试院机构时**不阻断**，只在该行备注留痕并在报告里给 `provenance_warnings` 计数，
  最终判断权留给运营，但疑点留在数据里。
- `/api/health` 的 `school_lines.official_landing` 上报通道是否就绪、待落库与拒收行数。

### S8-A 官方原表解析落库 + 溯源台账

S7-A 只解决了「校验与落库」，S8-A 补齐**投喂闭环**：省考试院公布的投档情况表列名各省不同
（如广东「投档最低分 / 投档最低排位」），人工整理成专用 JSON 既慢又易错。

- `school_lines.parse_official_table()` 直接吃 **CSV / XLSX / JSON**，按 `HEADER_ALIASES`
  识别表头（已扩充「投档最低分」「投档最低排位」「院校专业组代码」等考试院常见写法），
  年份 / 省份 / 科类 / 批次 / 来源链接可由命令行或表单统一指定，无需逐行填。
- CLI：`scripts/import_official_table.py <表> --province 广东 --year 2024 --subject 物理类
  --source-url <考试院原表地址> [--dry-run | --commit] [--copy-to-landing]`。
  管理端「官方逐校投档线落库」上传走同一条链路。
- **溯源台账**：落库成功即往 `backend/data/official/sources.json` 写一条记录
  （文件名 / sha256 / 省 / 年 / 科类 / 来源链接 / 落库行数 / 拒收行数 / 操作人 / 时间），
  按文件名去重。管理端「官方溯源台账」表格可点开原表链接；`/api/health` 的
  `school_lines.official_sources` 上报文件数与覆盖省份。
  目的只有一个：**每行 `official` 数据都能追到「哪个文件、哪条链接」**。

### S8-B 证据门槛校准（按真实分布分层）

S7-C 的「≥10 条校线 / ≥5 所院校」是经验值。S8-B 用
`scripts/calibrate_evidence_gate.py` 把真实分布摆出来再定档：

| 档 | 条件 | 行为 |
| --- | --- | --- |
| `none` | < 3 条 或 < 2 所 | 样本近乎为零，**不下判断** |
| `thin` | 未达 full | 单侧降级为 `unverified`，但给出**方向性事实**（最易触及的院校 / 「没有可及 ≠ 都够不到」） |
| `full` | ≥ 10 条 且 ≥ 5 所 | 允许 `supported` / `refuted` |
| `refuted` 附加门槛 | ≥ 20 条 且 ≥ 10 所 | 「够不到任何院校」是**全称否定**，比「够得到某一所」需要更厚的样本 |

实测（14020 行 / 54 个省×科类组合）：校线条数 46–547、覆盖院校 46–96，**全部落在 `full`**
——说明门槛在当前数据下不触发，它只在稀疏导入（如官方试点只落几行）时起作用。
这正是保留它的理由：未来某个省只落了 3 行官方数据，也不能据此断言「你够不到任何院校」。
`/api/health` 的 `school_lines.evidence_gate` 上报各档命中数与阈值。

## 运行时落库说明

服务启动时由 `backend/db/seed.py` 将上述 JSON **幂等播种**到 SQLite（默认 `backend/data/xuefeng.db`，已 gitignore）：

| 表 | 来源文件 | 说明 |
| --- | --- | --- |
| `universities` | `universities_national.json` | 2868 所，含省/市/层次/性质/主管部门/标识码/985·211·双一流 |
| `elite_universities` | `universities.json` | 112 所权威清单（含军校与拆分校区），用于核验页按层次展示 |
| `admission_baselines` | `admission_real_baseline.json` + `admission_official_2024.json` | 每 (省, 科类, 批次) 一行；官方值覆盖估算值，保留 `data_source/line/school/year/source_url` |
| `majors` / `resources` | `shared/content.json` | 专业图谱与开源资源 |

- 播种以源文件 SHA-256 为签名，未变化则跳过；管理端「数据同步」可强制重灌（force）。
- 官方覆盖行在库中 `data_source='official'`（当前 48 行），其余为 `estimated`；接口逐层透出。
- 更换源文件（新增省份官方数据）后，重启服务或点一次同步即可生效，无需手工改库。
- 切换 PostgreSQL：设置 `XUEFENG_DATABASE_URL`，表结构由 SQLAlchemy 自动创建。

## 重要声明

所有数据仅供学习与研究参考，**正式填报请以考生所在省教育考试院公布的官方数据为准**。
官方覆盖层为 2024 年口径；新高考改革省份逐年微调，使用时应关注当年最新省控线。

## 官方数据主来源体系（P0/P1/P2，2026-10-24）

产品对数据的第一要求是**可靠、真实、准确**，因此官方（`official`）必须是主来源。
本节是围绕这个目标的治理设施：

- **P0 年度采集台账**（`services/acquisition.py` + 管理端「采集台账」页）：
  31 省 × 年份 × 数据类（省控线/逐校投档/一分一段）矩阵，登记采集进度
  （`data/acquisition_ledger.json`，gitignore），同时给出**库内实测覆盖**
  （official 行数 / 一分一段落盘 / 省控线批次），防止台账与实际两张皮。
  采集窗口 = 每年 6 月底至 8 月上旬；操作指南见 `docs/data-acquisition.md`。
- **P1 批量投喂**：`scripts/import_official_table.py --landing-dir <目录>` 扫描
  整目录逐文件落库（JSON 自带 meta 优先，CSV 用命令行参数兜底）。
- **P2 准确性体系**（`services/data_quality.py`）：
  1. **位次交叉校验**：official 行 `min_score` 经当年一分一段表反查，与原表
     `min_rank` 偏差超 25% 即在备注留痕（不阻断落库）；
  2. **跨年突变检测**：同校同专业组相邻两年位次变化超 50% 列入复核清单；
  3. **原表留档**：落库成功后原表字节按 sha256 存入 `data/official/archive/`
     （gitignore）——考试院链接失效后仍可复核，真实性不依赖外链存活；
  4. **一键体检**：`GET /api/admin/data-quality` 汇总官方覆盖、溯源台账、
     落地区待办、交叉校验复检、跨年突变、种子一致性。
- **同键官方优先**（`map_for`）：同年同校 official 与 estimated_real 并存时，
  推荐取数以官方口径优先，且 `data_source` 透传真实来源（不再写死 `school_line`）。
