# 一分一段表：跨省落地现状与下一批方案（2026-10-21）

目标：31 省 × 2022–2026 的**官方一分一段表**（省考试院「成绩分段统计表」），
可点开溯源、逐行可校验，落到 `backend/data/rank_tables/{year}/{province}.json`。

## 1. 三种口径（数据分级的硬边界）

| 口径 | 定义 | 允许入库 | 备注 |
|---|---|---|---|
| `official` | 省考试院原表，且附件为**机读**（xls/xlsx/带文本层 PDF/HTML 表） | ✅ 默认落盘口径 | 必须有 `source_url` + 附件 sha256 |
| `reprint` | 教育门户转录官方原表（附门户 URL + 所引官方来源），机读 | ⚠️ 需显式标注，UI 必须可见 | 不得冒充 official；后续拿到原表再升格 |
| `pending` | 官方仅有图片/扫描件，无文本层 | ❌ 不落数据 | 只登记「已知存在 + 链接」，等 OCR 或另寻机读通道 |

**当前纪律**：`pending` 一律不 OCR、不臆造（广东 2023 扫描件、四川 2025 图片表、
河北 2025 图片 PDF 均按此处理）。

重庆的关键细节（`provinces/chongqing.py`）：
1. **一年一个目录，四年三套路径**：2026 在 `/uploadFile/infopub/2026/ptgk/yfd/fdb.htm`
   （`ptgk` = 普通高考，新目录）；2025 在 `/2025/pg/yfd/fdb.htm`（`pg`）；
   2022–2024 原年度页已下线，官方 2025-06-25 发布「往年重庆市各类考生一分数段表」
   汇总页（`/2025/pg/hist/link_block.html`），逐年一个 `www{year}/{year}yfd.htm`
   归档副本。**目录不存在时门户返回 HTTP 200 + 首页 HTML（软 404）**，判据只能是
   索引页标题含「分数段表」，不能只看状态码。
2. **顶部只有人数、没有累计**：`663及以上 | 60` 两格行 = 该桶人数即累计，
   `top_note` 打 `663↑`。若当成普通 3 格行会整行丢掉，后面累计链仍自洽、
   查不出来（必须靠行型判断）。
3. **官方不印「本段人数 0」的分数段**：2024 物理缺 197/196/184/181、
   2026 物理缺 188、2024 历史缺 182、2023 物理缺 192/184，累计链依然接得上。
   所以**不能按逐分连续校验**，缺口记进 `subjects.*.omitted_scores`（口径事实），
   按「漏行」处理会误判。
4. **表底不齐**：常规止于 180（专科批线同值），但 2023 物理当年只印到 182，
   逐年的实际表底记进 `meta.score_floor`。
5. 「含加分」= 档案分（总分 + 政策加分），即投档位次口径；门户上的发布条目
   （2025 = content_6645、往年 = content_6648）只是跳转壳，`url` 字段与索引页一致，
   因此 `source_url` 直接记索引页，另存 `source_sha256_map` / `subject_url_map` 逐科类溯源。

北京的关键细节（`provinces/beijing.py`，跨年**换过载体**：HTML 表 → PDF）：
1. **3+3，全市一张「综合」表**：不分物理类/历史类，`SUBJECTS = ["综合"]`。
   北京的「综合」= 全体考生，与山东「综合」同义，**不可与 3+1+2 省的科类混用**。
2. **高分逐分、低分 10 分一档**：逐分段止于 380/390/400（逐年不同），之后是
   `370→379`…`100→109`。10 分档不是某个具体分数，混进 `rows` 会让位次失真，
   因此**单列 `subjects.*.buckets`**（`{range:[low,high], seg, cum}`），
   并用 `_check_buckets()` 校验「首档累计 = 末行累计 + 首档人数」以及档间链自洽——
   断一格就整份拒收。
3. **2022–2024 是 HTML 表**（`/html/gkgz/fujian/{year}/0625/<id>.html`），
   单元格里用 `&rarr;` 表示区间（`120&rarr;129`），必须 `html.unescape` 后才匹配；
   2026 的源 PDF 里还出现 `160-→169` 这种脏字符（多一个 `-`），
   `BUCKET_PAT` 写 `[-–—→]+` 才能容错——否则 2026 少一个 10 分档且没人发现。
4. **2025 起正文页只挂 PDF**（`/uploads/soft/<yymmdd>/<file>.pdf`），文本层可用。
   正文页常**同时挂「高考考生分数分布」与「单考考生分数分布」两个 PDF**，
   文件名看不出区别，只能逐个下载、按 PDF 首页标题 `endswith("高考考生分数分布")`
   筛（`parse_pdf` 里校验）→ `parse()` 捕获 `ValueError` 后换下一个候选。
5. **7 月另发的「专科考生分数分布」是另一个口径**（只含未被本科录取的考生），
   绝不并入本表；`discover()` 里也按 `"专科" not in text` 排除。
6. 表尾注「统计中的分数含全国性（照顾）加分」= 投档位次口径，记进 `meta.tracks`。
   顶部 `700以上`/`698分以上` 是截断桶（累计=本段），打 `top_note`。

上海的关键细节（`provinces/shanghai.py`，版式最简，坑全在口径）：
1. **3+3，全市一张「综合」表**，满分 660，分数恒三位数；每页一整块
   `分数|人数|累计人数`，没有并排多组，按 y 聚行即可（不需要安徽那种列簇聚类）。
2. **覆盖范围逐年变过，这是最容易踩的坑**：2022 印到 280、2023 印到 284（全分数段），
   2024 起官方改发「**本科录取控制分数线上**考生」分布表，止于本科线（2024/2026 均止于 403）。
   所以 `meta.coverage` 与 `meta.score_floor` **必须一起看**——本科线以下的分数在这两年
   根本没有位次，跨年比较位次前先判断两边的覆盖范围是否都包含该分数。
3. **表尾注与页脚混排在最后一行数据之后**：2022 是一句「注：体育类本科控制线下考生…
   另行公布。」，2024 起拆成「注：」+ 编号 `1./2./3./4.` 四条说明。它们都是版式噪声，
   不能当丢行（否则整份拒收）；但识别必须严格（`^(注[:：]|\d+[.、])` 或含「公布」），
   否则真数据行被吞。
4. **附件路径五年四个样**：2022 `/20220723/ytl/00.pdf`、2023 `/20230623/2_0.pdf`、
   2024 `/20240623/00.pdf`、2026 `/20260623/2/0.pdf`（`2` 目录下 0..11 张，0 才是普通类）。
   别想按规则拼，逐年登记；正文页里普通类排第一，后面才是艺术类/体育类/综合评价。
5. **艺术类/体育类/综合评价批次是另一个口径**（专业统考成绩 / 投档成绩 / 入围考生），
   不并入本表；`parse_pdf` 用首页标题全文匹配 `^20XX年考生高考成绩分布表$` 把
   它们挡在外面，`parse()` 捕获 `ValueError` 后换下一个候选。
6. **2025 只有扫描件**：公告页 `/page/02200/20250623/19540.html` 的 4 页 PDF 各是一张图、
   `pdfminer` 抽出 0 个字符 → 按纪律不 OCR，整年进 `KNOWN_GAPS`（同步时明确报
   「不 OCR」而不是静默跳过）。

辽宁的关键细节（`provinces/liaoning.py`，与浙江/安徽同族但两个新坑）：
1. **每页并排 4 组**，列锚点取**表头 `分数` 的 x 坐标**（每页重复 4 次）——
   不能按「每页 3 组」硬编码，也不需要聚类：锚点差就是组宽。
2. **人数与累计时合时分**：同一份 PDF 里，有的是 `217   6,245` 一格，
   有的是 `217`（x=214）与 `6,245`（x=254）两格。所以取法是
   「该锚点区间内的**所有数字**依次当 分数→人数→累计」，不能按固定单元格序号取。
3. **累计带千分位逗号**（`6,028`），先 `replace(",", "")` 再转 int；
   反过来，若按 `\d+` 直接匹配会把 6,028 拆成 6 和 028——累计瞬间变成个位数。
4. **0 人的分数段官方不印**（2023 历史 6 处、2025 物理 2 处），分数不连续但累计链自洽 →
   允许缺口，缺口写进 `subjects.*.omitted_scores`；这与「漏行」必须区分开。
5. **末页某组会提前结束**（只剩 2–3 组），不能因为「这一行凑不齐 4 组」就把整行丢掉——
   按锚点各自成行，凑不齐的组直接跳过。
6. 正文页同时挂 6 个 PDF（物理/历史/体育·物理/体育·历史/艺术·物理/艺术·历史），
   文件名无语义，**只认 PDF 首页标题**：`TITLE_PAT` 要求以「(物理|历史)学科类」结尾，
   体育·/艺术·同类表自然不匹配；`parse()` 还会核对标签与标题的科类是否一致。
7. 2023 的 PDF 带「禁止文本抽取」元数据，pdfminer 会告警但仍能抽；模块里把
   `pdfminer` 日志级别调到 ERROR 免刷屏（不是绕过保护，是这份文件本身可抽）。

江西的关键细节（`provinces/jiangxi.py`，版式最简单、口径两代）：
1. 单列、每页一整块 `分数 | 人数 | 累计人数`，**每页都重复表名**——
   表名行会被当成「只有 1 个数字」的怪行，必须按 `段表` / `一分一段表` 字样跳过；
   页脚「第 N 页，共 M 页」同理。
2. 顶部截断桶的**分数与人数挤在同一格**：`640及以上 20`，后面才是累计。
   取法是「该行所有数字依次当 分数→人数→累计」，正好 3 个；不用切字符串。
3. **2022/2023 是文理分科**（表名「本科文史分段表」「文史类本科一分一段表」/
   「本科理工…」），2024 起才是 3+1+2。落盘统一成 历史类/物理类，
   `meta.subject_scheme` 记 `文理分科`/`3+1+2`，`subject_aliases` 留痕。
4. 正文页同时挂**「三校生一分一段表」**（中职对口升学，另一套考生），
   靠表名匹配 `(文史|理工|历史|物理)` 挡住；三校生表标题里没有这四类字样。
5. 站内检索是 `POST /queryList`（前端 jpage 的 `proxyUrl`），参数含
   `unitid=309449 / webSiteCode=jxsjyksy / title=`，返回 JSON（`urls.pc` 是文章路径）。
   **同一篇文章会同时投到 `gsgg91`（公示公告）与 `tzgg92`（通知公告）**，
   `discover()` 优先取 `gsgg91`，与 `SOURCES` 的登记口径一致。
6. 站点 http/https 都通，`SITE` 统一用 `https://`（`source_url` 必须是 https）。

安徽的关键细节（**一份 PDF 两个科类、五年三个版式**，全落在 `provinces/anhui.py`）：
1. **版式**：每页横向并排 3–5 组 `分数|人数|累计人数`，组数不固定（末页会少几组，
   2023 文史末页只有 3 组）；数据列**右对齐**（同列右边界 x1 恒定，与位数无关），
   按 x1 聚成 3N 个列簇，簇号 //3 即组号、%3 即列号，组内自上而下、组间左右。
   **不能按表头文字定位列**——2026 把表头三格并成一段文本；也不能按 y 拼行——
   同一 y 上的多格属于不同分数段。
2. **跨年变过三次口径**：2022/2023 文理分科（表头写 `科类：文史/理工`，
   落盘映射为历史类/物理类并留痕 `subject_aliases`）；2024 起 3+1+2；
   2025 与 2026 的 PDF 生成器不同（表头合并方式不一样）。
3. **表尾三种写法**：2022 是带数字的末行桶 `200及以下 | 17015 | 182811`
   （落 `below_bucket`，与上一行分数不接续但累计能接上）；2023–2026 是
   `200以下略` 截断说明（落 `omitted_below`，不再逐分列出）。
4. **两个黏连行坑**（pdfminer 把同一基线上的两段文本并成一行）：
   - `'137403 200以下'`（2025）= 累计列数字 + 右侧**游离注释**；
   - `'162638 200及以下'`（2022）= 上一组累计 + 下一组**分数格**；
   - `'144375200 以下'`（2023）= 累计 + 分数格，且中间**无空格**——
     拆分必须**懒惰匹配**（取最短累计位数）否则错拆成 `'14437520'`+`'0 以下'`。
   拆出的注释格保留整行右边界（x1 精确），由「能否落入某个列簇」自动区分
   游离注释与分数格；行聚簇用容差比较，不能用 `round(y/tol)`（实测同一行
   单元格 y 可差 0.3pt，会把一行劈成两行）。
5. **来源**：2025/2026 在省教育厅信息公开页（`jyt.ah.gov.cn/public/7071/<id>.html`）；
   2022–2024 该栏目尚未建立（二分探测确认单元下界 40757397 = 2025-06-25），
   原表在考试院官网固定路径 `ahzsks.cn/an-hui-sheng-<年>kskscjfdb.pdf`，
   以原表 URL 本身作 `source_url`。阳光高考（chsi）有同年镜像但 412 反爬，
   Wayback 沙箱不可达，均未采用。

湖北的关键细节：表内统计人数**含政策性加分**（表头注明），与广东「本科档/专科档」口径不同源。
**湖北只有 2025 是 PDF**：2024 通知页正文是 10 张 JPG（`W0202406..._ORIGIN.jpg`），
2026 在省考试院侧同样是图片，2022/2023 未在该栏目找到——四年的缺口属 `pending`，不 OCR。
湖南的关键细节（跨年**变过口径**，必须按年看 `meta.columns`）：
- 2022–2024 是双轨 5 列，主轨取**含全国性加分**（投档位次口径），地方性加分单列
  `alt_track`——它只对省属高校生效，混用会低估位次；公开报道的本科线人数用的是副轨，
  所以对锚点时要认轨。
- 2025 起改为单轨 3 列「含优惠加分」（地方性加分取消）。
- 表尾「100 分以下」桶：2024 起源表写 `100以下`，2025 那张却印成 `100`（与上一行同分），
  按「末行同分且累计能接上」识别并单列 `below_bucket`。
- 页面是 **GBK**，`decode_html` 按 `<meta charset>` 严格解码（旧实现按替换字符择优，
  会把 GBK 页按 utf-8 `errors=ignore` 解成乱码且自以为成功）。

陕西的关键细节（三列看着最简单，四个坑）：
1. 顶部截断桶**「人数」留空**：`710以上 | (空) | 11`，此时 人数=累计；
2. **分数不连续**：某分 0 人整行不印（700 后直接 698），不能校验「相邻差 1」；
3. 表尾是「N 分以下**及缺考**」，含缺考人数，单列 `below_bucket`；
4. 低分段是**两位数**（2022 表尾有 52/51/50），正则写成 `\d{3}` 会静默丢掉整段——
   已加「疑似数据未解析即整份拒收」的保护（这条是真踩过的 bug）。

山东是 3+3 省：`综合`=全体考生；`选考物理/化学/生物/思想政治/历史/地理`=该选考科目内部位次
（**不是**物理类/历史类，不可与 3+1+2 省的科类混用）。

## 6. 按省一键同步（S11：工具面）

采集不再是一个大脚本，改成「一省一模块 + 统一注册表」，因为最终要落到
**管理端按省一键同步**上——每个省必须能被单独触发、单独失败、单独留痕。

```
backend/rank_sync/
  common.py                 抓取（curl 兜底 + 错误页重试）/ 版式解析 / 强校验 / 落盘
  provinces/guangdong.py    广东：ZIP+PDF、逐类 PDF、无名合并 PDF 三种形态
  provinces/shandong.py     山东：xls 多档位宽表（3+3）
  provinces/zhejiang.py     浙江：并排 3 组 PDF（3+3 单表）
  provinces/hubei.py        湖北：每科类一份 PDF，并排 3 组
  provinces/hunan.py        湖南：官方 HTML 表格（单轨 3 列 / 双轨 5 列自适应）+ discover()
  provinces/shaanxi.py      陕西：官方 HTML 三列表（截断桶人数留空、分数不连续）
  provinces/anhui.py        安徽：一份 PDF 两科类，列右边界聚类（文理分科/3+1+2 三年版式）
  provinces/chongqing.py    重庆：一科类一张 HTML 表 + 索引页发现（ptgk/pg/hist 三套目录）
  provinces/beijing.py      北京：3+3 单表，HTML 表（2022–2024）/ PDF（2025–2026）+ 10 分档
  provinces/shanghai.py     上海：3+3 单表，PDF（每年一份）；本科线上/全分数段两代口径
  provinces/liaoning.py     辽宁：每页并排 4 组 PDF，人数/累计时合时分 + 千分位逗号
  provinces/jiangxi.py      江西：单列 PDF（2022/2023 文理分科 → 2024 起 3+1+2）
  __init__.py               31 省看板 + sync() 编排 + 状态台账
  __main__.py               CLI：python -m rank_sync [省份...] [--year] [--dry-run]
```

`provinces/` 里「发现」也归模块自己：湖南的 `discover()` 会翻 28 页列表页找
`档分1分段` 标题并解析年份/科类，用于校正 `NOTICES`（模块里存的是核对过的固定 ID，
自动发现只作辅助，避免每次同步都翻 28 页）。

三条入口共用同一个 `parse(year)`，不存在「按钮能跑、脚本不能跑」的分裂：

| 入口 | 用法 |
|---|---|
| CLI | `python -m rank_sync 湖北 湖南` / `--dry-run` / `python -m rank_sync`（只看板） |
| 管理端 | 校线导入页「按省同步一分一段表」→ 每省一个「同步」按钮 |
| API | `GET /api/rank-tables/provinces`（公开看板）、`POST /api/admin/rank-tables/sync`、`GET /api/admin/rank-tables/sync-status` |

同步语义：**抓取 → 强校验 → 落盘 JSON → 写 rank_segments**（`write_db` 可关）。
逐年份隔离失败；校验不过的年份整份拒收，不写半份文件。运行期台账写
`data/rank_tables/_sync_status.json`（已 gitignore，看板状态可由磁盘重算）。

看板现状（2026-10-21，S18 后）：**ready 12 省 / blocked 10 省 / planned 9 省**，
已覆盖 **49 个省·年**（江西 2022–2026 五年全落盘；辽宁/上海各缺一年，均因官方只发图片）。
`blocked` 必须带原因（扫描件、纯图片、412、不可达），
`ready` 省的缺口写进模块的 `KNOWN_GAPS`（如广东 2023 扫描件、湖北 2022–2024/2026），
避免下一批重复踩同一个坑。

新增一省的检查单见第 4 节；实现只需在 `provinces/` 加一个模块并在
`provinces/__init__.py` 登记，管理端按钮会自动出现。
