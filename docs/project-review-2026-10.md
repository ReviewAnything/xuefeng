## 0. 一句话结论

这是**一个思路清晰、代码干净、测试可跑的优质 v2 雏形**——"定性观点 × 定量数据交叉核验（P2）"是真正的核心差异点。但它目前最大的瓶颈是**录取数据的真实性/覆盖面**和**开源工程化缺失**。优先补这两块，它就能从 demo 走向可分发产品。

## 1. 项目是什么

把张雪峰「普通家庭 + 就业导向」框架与开源社区资源结合的**志愿决策助手**：
- 前端：uni-app（Vue3）一套代码出 H5 / 微信小程序 / App
- 后端：Python FastAPI 承载数据层（录取位次 / 冲稳保 / 观点×数据核验）
- 单一数据源：`shared/content.json`，前后端共用
- 五大模块：自我诊断画布 → 专业图谱库 → 观点×数据核验(P2) → 开源资源中心 → 关于

作者 `javaeer`，单 commit「INIT Project V2」（2026-10-19），是一个刚起步的项目。

## 2. 真正做对的地方（优点）

| 项 | 评价 |
|---|---|
| **P2 交叉核验** | 把"推荐/慎选/避坑"观点与用户位次可达批次做一致性判定（aligned/caution/conflict），是产品的灵魂，逻辑完整（`verify.py`） |

## 3. 必须正视的短板（按严重程度）

### P0 · 数据（决定产品值不值得用）
- **录取数据是"参数化样例"，只覆盖 6 省**：`admission_sample.json` 仅有 河南/广东/山东/四川/河北/江苏；`verify.vue:80` 前端省份 picker 也硬编码这 6 个。约 25 个高考省份完全不可用。
- **模型太粗**：单 baseline（省×科类×批次）+ 难度系数偏移（`score_add`/`rank_factor`），无院校/专业组粒度，无法反映"同分不同校、同校不同专业"的真相。
- **真实数据门槛高**：需用户自己从 `chenxuyaun/gaokao-advisor` 导出 CSV 再放进去，普通考生家长不会这步。
- **样例取值未必准**：如河南物理类专科 `min_rank: 550000`，且 `DATA_DATE: 2026-10-19` 但内容实为社区整理，缺少逐条出处的 `source_year` 字段。

### P1 · 工程 / 产品
- **无缓存，每次请求重读数据**：`admission.py:_load_sample()` / `_load_real_rows()` 在每次 API 调用时重新 `json.load` / 读 CSV。真实 21.7 万行 CSV 会慢 → 需启动时加载到内存或 SQLite。
- **P1 与 P2 没打通**：诊断画布是纯前端生成的框架（`engine.js`），"数据侧核验"（`diagnose.vue` ③）只调 `search`，canvas 的推荐专业不能一键带入 P2 核验，用户得手动重填。
- **输入校验弱**：`classify()`（`admission.py:77-88`）当 `user_rank=0` 时 `ratio=0 < 0.85` 会判"保"；应校验 `user_rank > 0` 及合理上界。
- **CORS 全开**：`main.py:31` `allow_origins=["*"]`，上线 H5 / 小程序有风险，应改为环境变量白名单。

### P2 · 开源 / 合规
- **⚠️ 仓库没有 LICENSE 文件**（文件树已确认）：作为"开源项目"，这是首要缺口，会直接劝退贡献者。
- **无 CI**：没有 `.github/workflows`，质量靠人工。
- **lockfile 双份**：同时存在 `package-lock.json` 与 `pnpm-lock.yaml`，工具链不一致。
- **依赖锁到 DCloud 日期快照**：`3.0.0-5020620260917001`（2026-09-17 构建），可复现性差。
- **dead 依赖**：`vue-i18n` 声明但未使用。
- **实名与商业化关联**：大量使用"张雪峰"实名并链接其商业化 skill 仓库；免责声明已有，但建议再加"非关联 / 仅供参考"的醒目提示。

## 4. 方向建议（按优先级，可落地）

### P0 — 把"数据"做成护城河
1. 写 **ingestion 脚本**：自动拉取 `gaokao-advisor` 21.7 万条，规范 schema（省份名映射、批次推断），先 **seed 6 省真实数据**让 app 开箱即用真实数字。
2. 把 `verify.vue` 省份 picker 扩到全部 31 省（样例基线同步补齐），一步扩大可用性 5 倍。
3. 数据粒度从"单 baseline"升级到**学校 + 专业级真实查表**（至少专业级）。

### P1 — 打通流程 + 性能/正确性
4. 诊断画布的推荐专业支持**一键批量核验**；`/api/admission/search` 可接收 canvas 的过滤条件（stable/subject），让数据侧列表尊重用户策略。
5. 启动时把 admission 数据载入内存 / SQLite，加缓存；CSV 改为按需加载。
6. 输入校验 `user_rank > 0`、合理上界；CORS 改环境变量白名单。

### P2 — 开源就绪
7. 加 **LICENSE**（MIT 或 Apache-2.0）+ CONTRIBUTING。
8. GitHub Actions：push / PR 跑 `pytest` + `node engine test`。
9. 统一 lockfile（建议 pnpm），删除 `vue-i18n`，约束依赖版本区间。
10. 提供 `docker-compose` 一键起前后端，降低贡献门槛。

### 产品 / 分发
11. **部署一个公开 H5 demo**（about 页有架构但无在线地址）——高考家庭才是真实用户，能体验才谈得上增长。
12. **内容可溯**：给每个专业加 `source_year` / `source_note` 字段，呼应"事实可溯源"原则。
13. 后续 P3/P4 路线：院校推荐（按分输出院校+专业）、等位分换算、新高考**院校专业组**支持、导出志愿表 PDF。
